互动教学 · 抗锯齿

为什么直线会“吃齿”，怎么把它磨平？

抗锯齿不是魔法，而是一套“把像素边缘变得更像连续曲线”的策略。这个教程会用交互演示带你看清：为什么会出现锯齿、有哪些常见实现方法、当前仓库怎么做，以及主流 2D 图形库通常怎么做。

1. 先理解问题 你看到的“锯齿”其实是离散像素对连续几何的近似误差。
2. 再看方法 超采样、解析式覆盖度、后处理滤波各有优缺点。

这页要带你掌握的 4 件事

  • 什么是抗锯齿，以及为什么它在像素栅格里是必要的。
  • 3 类常见实现方法：超级采样、解析式 AA、后处理 AA。
  • WhatsCanvas 当前实际采取的做法：几何扩边 + coverage fringe。
  • Skia、Cairo、Qt、浏览器 Canvas 等库通常会怎么做。
01 · 先看问题

为什么屏幕上的斜线会“吃齿”

上图把一条斜线按像素网格“打散”。左上角像素是 0/1 采样，右下角则用更细的子采样来得到半透明覆盖度。你可以把滑块拉大，看到边缘的“灰度过渡”是如何变得更平滑的。

核心直觉 连续几何 → 离散像素 一个像素只能表示“占据 / 不占据”这两种极端， 如果我们把边缘附近的像素按覆盖率混合，就能得到更像连续线的视觉效果。

这就是抗锯齿的本质：不是把几何“变得更复杂”，而是让像素边缘表达“部分覆盖”的信息。

一个最小例子 假设某像素只被直线覆盖了 30%， 那它就不必被硬生生地画成全黑或全白， 而可以用 30% 的强度表示。

这就是覆盖度（coverage）概念：同一个像素在不同子采样点上的命中率。

02 · 3 种常见方法

超采样、解析式 AA、后处理 AA，三者各自怎么做

超采样（SSAA / MSAA）

在一个像素里额外采样多次，再把结果平均。

解析式 AA（Analytic AA）

不靠多采样，而是把几何边缘“扩成一带”并给出覆盖度。

后处理 AA（FXAA / SMAA）

先渲染一张有锯齿的图，再用滤波器“修边”。

超采样（SSAA / MSAA）

把一个像素拆成若干个子采样点，分别判断是落在线内还是线外，最后把命中率平均出来。它直观、容易理解，但代价较大。

      03 · 当前仓库怎么做

      WhatsCanvas 现在走的是“几何扩边 + 覆盖度”路线

      从源码看，当前项目的思路不是传统的 MSAA，而是把填充/描边几何沿轮廓扩出一层“羽化带”，再把这层覆盖度传给片元着色器：

      // src/render/AntiAlias.h
inline float featherWidthPixels() {
    return 1.0f;
}
      // src/canvas/Canvas.cpp
// Interior triangles keep coverage 1.0;
// fringe triangles get coverage ramping from 1.0 to 0.0.
mesh.coverage.push_back(1.0f);
mesh.coverage.push_back(cov);
mesh.coverage.push_back(cov);

      这意味着：形状真实边缘附近会多出一圈“半透明边”，浏览器或屏幕看到的结果就不会再像“硬切”的像素台阶。

      1. 先把几何边缘变成“有覆盖度的三角带” 在 Canvas 的路径三角化阶段，程序会沿形状轮廓额外生成一小段围边三角，覆盖度从 1 到 0 平滑变化。
      2. 再把 coverage 传给渲染器 片元着色器按插值覆盖度去乘 alpha，边缘就会显得更平滑，而不是全黑/全白的像素阶梯。
      3. 裁剪路径也用同样思路 src/opengl/ClipCoverageProgram.cpp 里会把裁剪路径的 AA 覆盖度光栅化成一张 R8 掩码，绘制时按覆盖度调制 alpha，得到圆滑裁剪边缘。
      04 · 主流 2D 图形库怎么做

      Skia、Cairo、Qt、浏览器 Canvas 都有自己的取舍

      Skia

      常见于 Chrome / Android / Flutter。它把路径栅格化做得很成熟，既有解析式路径 AA，也会在不同后端上适配不同采样与滤波策略。

      Cairo

      偏 CPU 2D 向量渲染，通常基于扫描线和覆盖度/像素级混合做边缘平滑，重视稳定性和可移植性。

      Qt / QPainter

      把绘制抽象成 PaintEngine，平台差异很大，但整体上会在路径、文本、图像上做一层覆盖度与滤波平衡。

      浏览器 Canvas 2D

      浏览器背后会把这件事交给其渲染引擎；对开发者来说，通常只需要关心“是否开启抗锯齿”和“图形质量/性能之间的平衡”。

      结论：主流库的共同点是“边缘不是 0/1 二值，而是用覆盖度、羽化带或滤波让视觉更接近连续线”；不同点是它们把成本放在了 CPU、GPU、纹理、栅格器还是后处理阶段。
      05 · 你可以怎么判断

      什么时候该选哪种实现

      想要最直观、最容易理解 选超采样；如果你的目标是教学、单机 demo、静态图而不是极致性能，SSAA 很有帮助。
      想要高性能、可扩展到实时渲染 选解析式 AA；尤其像 SVG、路径、矢量图和 2D UI 这种场景，几何覆盖度是很常见的方案。
      想要快速补救已有图像 选后处理 AA；它适合现成渲染结果的“锦上添花”，但对几何边缘的控制一般不如前两种精细。
      一句话总结 抗锯齿的本质是“把边界从 0/1 变成覆盖度”， 而不同方法只是把这件事放在不同阶段完成： 采样阶段、几何阶段，还是图像后处理阶段。
