左侧每个方块代表一个真实存在的处理阶段。很多人以为“渲染文字”就是 for each char: draw(char)，但实际上字符在变成像素之前， 要先经过编码、查表、塑形、定位、栅格化、上传 GPU 等多个环节。

核心观念 字体不是图片，而更像一段“程序”：它存的是轮廓和规则，真正的像素是渲染器在运行时算出来的。 所以同一个字体文件，在不同字号、不同系统、不同渲染器下，画出来的像素可以完全不同。

三条贯穿全程的主线

主线 A

字体格式的演化

点阵字体 → 矢量字体 → OpenType → 可变字体 → Web 字体。每一步都在解决“分辨率、存储、排版能力、分发效率”里的某个问题。

主线 B

字符到像素的链路

字符 → cmap → 塑形 → 度量 → 轮廓 → 栅格化 → 图集 → GPU。这是整套教程的技术骨架。

主线 C

语言与平台的差异

英文、CJK、阿拉伯（从右到左）在塑形与排版上规则不同，这正是 HarfBuzz 这类库存在的原因。

开始前，先想一个问题 🤔

当你在编辑框里输入 fi 两个字符，屏幕上最终画出的，一定是两个独立的字形吗？

看看答案

不一定。很多字体里 f + i 会被“连字（ligature）”合并成 一个 字形 fi， 避免 f 的顶部和 i 的点撞在一起。也就是说：字符数 ≠ 字形数。这正是第 4 章「文本塑形」要讲的核心。
