互动教学 · Canvas 里的数学

2D 图形库里到底用了哪些数学？

很多人觉得"画图 API 就是调 drawRect"——但一旦你想画个旋转的按钮、一条 Bezier 曲线、或一个径向渐变，背后就是几百年前的数学在替你算。这个教程会带你看清：2D 向量怎么描述几何、矩阵怎么表示 translate/rotate/scale、Bezier 曲线为什么要"扁平化"、渐变怎么从 t ∈ [0,1] 映射到颜色、距离场怎么给抗锯齿服务、重心坐标怎么插值颜色。每一节都有交互演示 + 真实场景。

1. 数学是可视的 向量、矩阵、参数方程都能在屏幕上直接"看"到，不是纸上抽象符号。
2. 每条 API 都有它背后的公式 canvas.rotate(θ) 就是矩阵乘法；drawPath(bezier) 里必有 de Casteljau。

这页要带你掌握的 6 件事

  • 2D 向量 & 叉积：判断"P 在直线的哪一侧"这一件事。
  • 变换矩阵：为什么 2D 也要 3×3（齐次坐标），4×4 又是从哪来的。
  • Bezier 曲线：de Casteljau 递归、flatten 到直线段的判据。
  • 渐变的参数化：linear / radial 各自的 t = f(pixel) 公式。
  • 距离场 (SDF)：抗锯齿边缘 / 阴影 / 圆角 / 文字 subpixel 都用它。
  • 重心坐标：颜色插值、UV 采样、覆盖度插值的通用工具。
01 · 从最基础开始

2D 向量：一个"箭头"，两种运算

在画布上拖动两个端点 A、B。右下角实时显示：向量 AB = B − A、长度 |AB|、法向量、与 x 轴的夹角。你会看到"向量"就是一条有方向的箭头，做减法就得到从 A 到 B 的位移。

向量的加/减/长度 v = (x, y) |v| = √(x² + y²) ← 勾股定理 AB = B − A ← 从 A 到 B 的位移 角度 θ = atan2(y, x) ← 与 x 轴夹角

这就是 drawLine(A, B) 里 API 层最底下的东西。Canvas 上每一次"从这儿到那儿"都是一个向量。

点积（Dot Product）· "有多相似" a · b = a.x × b.x + a.y × b.y = |a| × |b| × cos(θ) θ = 0° → a · b 最大 （方向完全相同） θ = 90° → a · b = 0 （垂直） θ = 180° → a · b 最小 （方向完全相反）

用途：判断"点是否在圆锥内"（用于 hit-testing 扇形按钮）、光照方向的余弦分量、渐变里"投影到方向轴上的距离"。

叉积（Cross Product）· "在哪一侧" + "面积" a × b = a.x × b.y − a.y × b.x 结果 > 0 → b 在 a 的逆时针一侧（y-down 里是"下方"） 结果 < 0 → 顺时针一侧 结果 = 0 → 共线 |a × b| → a、b 张成的平行四边形面积

用途：三角形填充、路径 fill rule、光栅化边函数都用它。栅格化与缓存 教程里的 edge() 就是叉积。

02 · 变换 = 矩阵

canvas.translate/rotate/scale 背后就是一次矩阵乘法

左边是原始正方形（单位坐标系），右边是套了 translate → rotate → scale 之后的效果。滑块改变每个参数，看单位圆和坐标轴如何跟着变换。顺序有意义：先 rotate 后 translate ≠ 先 translate 后 rotate。

2D 变换的"齐次形式" 用 (x, y, 1) 三个分量表示一个 2D 点。 用 3×3 矩阵表示"一个变换"： M · (x, y, 1)ᵀ = (x', y', 1)ᵀ

加了一维"1"是为了让 平移 也能用矩阵乘法表达（否则平移必须单独加减）。这个"多一维"的技巧叫齐次坐标，18 世纪的数学家发明的。

三种基础矩阵
Translate(tx, ty):
10tx01ty001
Rotate(θ):
cos−sin0sincos0001
Scale(sx, sy):
sx000sy0001

"变换链"就是矩阵相乘。canvas.translate(tx, ty); canvas.rotate(θ) 等于 T · R。乘法从右到左"读"：先 rotate 再 translate。

为什么 WhatsCanvas 用 4×4 而不是 3×3 glm::mat4 transform = glm::mat4(1.0f); // (x, y, 0, 1) —— z 保留给未来 depth，w 保留齐次除法

GLSL / GL 传统上都是 4×4；src/command/DrawData.h 里 glm::mat4 transform 就是这个原因。虽然 z 分量 = 0，但 4×4 让 CPU/GPU 传递格式统一。

03 · Bezier 曲线

拖动控制点，看 de Casteljau 一层层"套娃"出曲线

4 个可拖动的控制点定义一条三次 Bezier 曲线。中间几层的插值点让你直观看到"de Casteljau"这个递归。橙色的点就是 t 对应的曲线点。底部小图展示同一曲线用不同 flatten 阈值离散成的折线——越小越平滑但顶点越多。

三次 Bezier 曲线（cubic） P(t) = (1−t)³ P₀ + 3(1−t)²t P₁ + 3(1−t)t² P₂ + t³ P₃ (t ∈ [0,1])

这是"Bernstein 多项式"展开的形式。字体设计、Illustrator、Photoshop、Path API 都用这个。

de Casteljau 递归 Q₀ = lerp(P₀, P₁, t) Q₁ = lerp(P₁, P₂, t) Q₂ = lerp(P₂, P₃, t) R₀ = lerp(Q₀, Q₁, t) R₁ = lerp(Q₁, Q₂, t) P(t) = lerp(R₀, R₁, t)

数值上更稳定，直观易理解。拖动 t 滑块就能看到三层 lerp 塌下来到一点——那个点就是曲线上的位置。

为什么要 flatten GPU 光栅器不吃曲线，只吃三角形。 所以 Canvas 需要把曲线"扁平化"成一串折线： ▪ 判据 1：曲率半径 > 阈值就分裂 ▪ 判据 2：控制点偏离直线 > 阈值就分裂 ▪ 判据 3：常用的"最大误差 < 0.5 pixel"

nanovg / stb_truetype / cairo / WhatsCanvas 都有自己的 flatten 逻辑。阈值调小 → 曲线更平滑 + 顶点更多；调大 → 更省 CPU 但可能看得出多边形轮廓。

04 · 渐变

Linear vs Radial：t = f(像素) 的两种参数化

拖动两个端点。左边是渐变结果，右边是该像素的 t 值（用灰度表示 t ∈ [0,1]，黑 = 0，白 = 1）。理解了"每个像素怎么算 t"，你就理解了所有渐变的本质。

Linear Gradient · 投影到方向轴 给两个点 start、end 定义方向。 对每个像素 P： d = end − start （方向向量） t = ((P − start) · d) / (d · d) （投影 + 归一化） color = 沿 t ∈ [0,1] 采样 gradient stops

用了向量点积！(P − start) · d 就是"P 相对 start 在 d 方向上的投影距离"，除以 |d|² 归一到 [0,1]。

Radial Gradient · 圆心距离 给中心点 c 和半径 r。 对每个像素 P： t = |P − c| / r （距离归一化） color = 沿 t ∈ [0,1] 采样

用了勾股定理算距离。t > 1 时通常 clamp 到 1（或 tile mode 指定为 repeat / mirror）。

沿 t 采样 gradient stops stops = [(0.0, red), (0.5, yellow), (1.0, blue)] 对给定 t： 1. 找到 t 落在哪两个 stop 之间 2. lerp(color_i, color_{i+1}, (t − t_i) / (t_{i+1} − t_i))

这就是 Paint::setLinearGradient(...) 底下发生的事。GPU 后端把它塞进 fragment shader；Software 后端用 CPU 循环每像素算一次。

05 · 距离场

SDF：把"这个像素离图形多远"变成一个可微函数

左：形状实心填充。中：距离场可视化（每像素到形状边界的距离，负号在内，正号在外）。右：用距离场做抗锯齿——距离 < 0 = 内部；|距离| < 边缘宽度 = 平滑过渡；否则 = 外部。这就是 SDF-based AA。

SDF：Signed Distance Function sdf(P, shape) = 到 shape 边界的最短距离 < 0 → P 在 shape 内 = 0 → P 在边界上 > 0 → P 在 shape 外

数学上就是"边界的最近点距离带上符号"。对常见形状有解析式 SDF：圆 = |P − c| − r；圆角矩形是"距边界最短距离再减 r"。

三种典型形状的 SDF Circle(c, r): sdf = |P − c| − r AABB (x0, y0, x1, y1): d = (max(x0 − P.x, P.x − x1), max(y0 − P.y, P.y − y1)) sdf = length(max(d, 0)) + min(max(d.x, d.y), 0) RoundedRect(bounds, r): sdf = sdf_of_inset_rect(bounds − r) − r

"矩形 SDF 里的 max/min"就是把内、外两种情形合并到一条公式里。这是所有 shader-based 2D 图形（Signal / Rive / imgui 的圆角）的核心。

用 SDF 做抗锯齿 float coverage = 1 − smoothstep(−0.5, 0.5, sdf); sdf = -1 → coverage = 1 （内部） sdf = 0 → coverage = 0.5（边界正中） sdf = 1 → coverage = 0 （外部）

这也是抗锯齿教程里"解析式覆盖度"的另一种实现方式。WhatsCanvas 走的是"几何 fringe + 顶点覆盖度"，SDF 是它的姊妹方案——各有取舍。

06 · 重心坐标

三角形里的"权重"：从颜色插值到 UV 到覆盖度

拖动 P 点。三个顶点分别是红、绿、蓝，P 处的颜色 = 三种颜色按 (b0, b1, b2) 权重混合。右下角显示三个权重的值。这就是 GPU fragment shader 里的 "varying" 变量自动做的事。

插值公式 对三角形的顶点 v0, v1, v2 和它们的属性 X0, X1, X2： X(P) = b0 × X0 + b1 × X1 + b2 × X2 其中 (b0, b1, b2) 是 P 的重心坐标： b0 + b1 + b2 = 1 b_i ≥ 0（P 在三角形内）

属性可以是：颜色、UV 纹理坐标、覆盖度 (AA)、法线（3D）、任何"每顶点一个值"的东西。

怎么算 b0 / b1 / b2 用边函数（就是叉积）： area = edge(v0, v1, v2) ← 大三角形面积 × 2 b0 = edge(v1, v2, P) / area ← 对面小三角形 b1 = edge(v2, v0, P) / area b2 = edge(v0, v1, P) / area

CPU 光栅器算完 3 个边函数就顺便有了 3 个 barycentric，一次循环把 in/out 判定和插值都做完。GPU 硬件光栅器发射 fragment shader 时也把它们塞进去。

典型用途 1. 颜色插值：drawTriangles + vertex colors 2. UV 采样：drawImage 里的三角形展开 3. 覆盖度插值：analytic-AA 的 fringe 三角形 4. Gradient 属性：局部坐标的 lerp 5. Path 属性：per-vertex feature 分布

这也是为什么"GPU 抽象"里最基础的两件事是"顶点属性"和"varying / in"——重心坐标是它们背后的引擎。

07 · 颜色 & Gamma

为什么 0.5 灰不是"中间灰"，直到你走 linear 空间

上排是 sRGB 空间的均匀渐变（大多数图形 API 默认行为）——你会看到中间跳过了很多"应该是灰色"的过渡；下排是先转到 linear 空间做插值、再转回 sRGB 的结果。物理上正确的中间灰应该看起来"更暗"，因为人眼对暗部更敏感。

sRGB → Linear 的转换 // 简化近似 (gamma 2.2) linear = sRGB^2.2 // 精确 IEC 61966-2-1 定义 if (sRGB ≤ 0.04045) linear = sRGB / 12.92 else linear = ((sRGB + 0.055) / 1.055)^2.4

监视器发光 ≈ 输入信号^2.2（历史 CRT 特性沿用至今）。sRGB 值不是线性的亮度——把 0.5 直接当"一半亮度"是错的。

正确的颜色混合：先 → linear // 错的做法（大多数 Canvas API 默认） mid_srgb = (color_a_srgb + color_b_srgb) / 2 // 对的做法（物理正确） a_lin = sRGB_to_linear(color_a_srgb) b_lin = sRGB_to_linear(color_b_srgb) mid_lin = (a_lin + b_lin) / 2 mid_srgb = linear_to_sRGB(mid_lin)

红 → 绿 渐变尤其明显。sRGB 直接混合中间是浑浊的褐黄；linear 混合中间会有明亮的黄。WhatsCanvas 通过 GammaCorrect::enabled() + GL_FRAMEBUFFER_SRGB 支持这个选项。

什么时候必须走 linear：渐变、透明度合成、光照计算、模糊（尤其阴影）、色彩纠正 LUT。
什么时候不必：纯 UI 图标、复制像素、text glyph（那些通常已经 gamma-corrected，改反而错）。
08 · 3D 投影矩阵

4×4 矩阵 + 齐次除法 = 从 3D 世界到 2D 屏幕

拖动画面看一个旋转的立方体从 3D 世界投影到 2D 屏幕。红色是"齐次除法"的作用——距离摄像机越远的顶点被 w 除得越小，看起来就"缩得越厉害"，这就是透视。FOV 变大 = "广角"，FOV 变小 = "长焦"。

3D → 2D 完整流水线 点 P (x, y, z, 1) ↓ Model · 物体的变换矩阵 ↓ View · 相机的逆矩阵 ↓ Projection · 透视 / 正交投影 点 P' (x', y', z', w') ← 齐次坐标 ↓ 齐次除法 (÷ w') → (x'/w', y'/w', z'/w') ← NDC 空间 [-1, 1] → 视口变换 ← 屏幕像素

这就是"MVP 矩阵"名字的由来 —— Model × View × Projection。GPU 的 vertex shader 主要就在做这条流水线的前 4 步。

透视投影矩阵 f = 1 / tan(FOV / 2) aspect = width / height [ f/aspect 0 0 0 ] [ 0 f 0 0 ] [ 0 0 (n+f)/(n-f) 2nf/(n-f) ] [ 0 0 −1 0 ]

最后一行 [0, 0, −1, 0] 是关键。乘完之后 w' = −z——离摄像机越远（z 越负），w' 越大，除完后 x/y 越小，看起来就越"远"。这就是 透视缩短。

正交投影（Orthographic） glm::ortho(left, right, bottom, top) 对每个点： x' = 2(x − left) / (right − left) − 1 y' = 2(y − bottom) / (top − bottom) − 1 w' = 1 ← 保持不变 没有齐次除法，也就没有透视缩短。

2D 图形库全部用正交投影，包括 WhatsCanvas。DrawPathProgram::draw 里的 glm::ortho(0, width, height, 0) 就是它——把画布像素坐标直接映射到 NDC。

09 · 插值曲线

动画的灵魂：从 lerp 到 smoothstep 到 ease-in-out

上：不同 easing 函数在 [0,1] 上的曲线形状。下：一个小球用当前 easing 函数做 A → B 位置动画（点画布重启动画）。体会：linear 看起来"机械"，smoothstep 看起来"自然"，bounce/back 提供动感。

lerp：所有 easing 的基石 lerp(a, b, t) = a + (b − a) × t = (1 − t) × a + t × b t = 0 → a t = 1 → b t = 0.5 → 中点

所有渐变、动画、混合、插值都基于它。GLSL 里的 mix(a, b, t) 就是 lerp。

smoothstep：3 次 Hermite 曲线 smoothstep(t) = t² × (3 − 2t) t = 0 → 0 t = 1 → 1 t = 0.5 → 0.5 在两端"减速"——导数在 0 和 1 处 = 0 smootherstep(t) = t³ × (6t² − 15t + 10) 更平滑的 5 次多项式（Perlin 用它）

用途：抗锯齿边缘（05 · SDF 里的 smoothstep(-0.5, 0.5, sdf)）、渐变边界柔化、程序化纹理。

Cubic Bezier easing CSS 里的 cubic-bezier(x1, y1, x2, y2)： P₀ = (0, 0) P₁ = (x1, y1) ← 控制点 P₂ = (x2, y2) ← 控制点 P₃ = (1, 1) 就是 3 次 Bezier 曲线（同 03） 只是把 t 映射到 y 值当作 easing 曲线

这就是 CSS transitions / SVG SMIL / Flutter Curves 底下的东西。回到 03 · Bezier——你已经会画它了。

10 · 三角学 & 极坐标

旋转、粒子、罗盘的通用工具：sin/cos + atan2

左：单位圆 + 一个旋转点，实时显示 sin/cos。中：极坐标（r, θ）到笛卡尔 (x, y) 的转换——n 个花瓣的花朵。右：把 30 个粒子在圆周上均匀分布 = angle_i = 2π × i / N 的应用。

笛卡尔 ↔ 极坐标 笛卡尔 (x, y) → 极坐标 (r, θ)： r = sqrt(x² + y²) θ = atan2(y, x) 极坐标 (r, θ) → 笛卡尔 (x, y)： x = r × cos(θ) y = r × sin(θ)

"极坐标 gradient"就是这个思路：中心到当前像素的方向角 θ 对应一个色轮上的颜色。

粒子/花瓣分布：均匀角度 for i in 0..N: θ_i = 2π × i / N x_i = cx + r × cos(θ_i) y_i = cy + r × sin(θ_i)

粒子系统、圆形菜单、雷达图、饼图、钟表、n-边形——全部用这一个模式。

atan2 vs atan atan(y / x) → 只知道 y/x 比值， 返回 [−π/2, π/2]，不能区分象限 atan2(y, x) → 输入 y 和 x 两个数， 返回 [−π, π]，正确区分 4 个象限

写图形代码几乎永远用 atan2，不用 atan。前者能正确处理 x=0 和不同象限。

11 · 卷积

图像滤镜的通用工具：一个 kernel 决定一切效果

左：源图（几何图案）。中：所选的 3×3 kernel。右：卷积结果。同一个数学操作（每像素 = 邻居 × 权重求和）产生所有这些效果，只是权重矩阵不同。

离散 2D 卷积 output[x, y] = Σᵢ Σⱼ kernel[i, j] × input[x+i, y+j] 其中 (i, j) 在 kernel 的作用域内循环。 kernel 通常是 3×3、5×5 或更大的奇数方阵。

"每个像素"变成了"邻居们的加权和"。权重决定了效果：全 1/9 = 模糊；正负交替 = 边缘检测；中心大 + 周围负 = 锐化。

常见 kernel Box blur (3×3): 1/9 × ⎡1 1 1⎤ Gaussian σ=1 (3×3): ⎣1 1 1⎦ 1/16 × ⎡1 2 1⎤ ⎣1 1 1⎦ ⎣2 4 2⎦ ⎣1 2 1⎦ Sharpen: Sobel-X (边缘): ⎡ 0 −1 0 ⎤ ⎡ −1 0 1 ⎤ ⎣−1 5 −1 ⎦ ⎣ −2 0 2 ⎦ ⎣ 0 −1 0 ⎦ ⎣ −1 0 1 ⎦

Gaussian 是"归一化的钟形分布"离散化。它在滤镜（离屏渲染 里提到过）里是模糊的黄金标准，因为它可以拆成 可分离 的两次 1D 卷积（省算量）。

可分离性（Separable） 2D Gaussian = 1D Gaussian × 1D Gaussian 所以 N×N 卷积可以拆成两次 N 次 1D 卷积： N² 次乘法 → 2N 次乘法 3×3 kernel: 9 → 6，节省 33% 5×5 kernel: 25 → 10，节省 60% 9×9 kernel: 81 → 18，节省 78%

这就是 WhatsCanvas GaussianBlurProgram 两 pass 实现的原因——一次横向、一次纵向。

12 · 采样与走样

为什么图片缩小会有 moire？—— 香农定理不饶人

缩小同一张棋盘图。Nearest 采样（最近邻）会出现 moire 干涉纹——高频细节在低采样率下"混叠"；Bilinear（双线性插值）不会消除 moire 但会更柔和。真正解决 moire 要靠 mipmap 或 anisotropic filter。

Nyquist–Shannon 定理 要正确重建一个信号， 采样频率必须 ≥ 信号最高频率 × 2 违反 → aliasing（走样）： 高频"折叠"回低频， 变成新的、假的信号（moire）

图像里的"频率"是"变化速度"。棋盘格 = 高频；纯色 = 低频。缩小图片 = 降采样率 → 高频细节没法被表示 → aliasing。

Bilinear：4 个邻居加权平均 tex_x = 采样点在源图的 x 坐标（可能小数） tex_y = 采样点在源图的 y 坐标 x0 = floor(tex_x), fx = tex_x − x0 y0 = floor(tex_y), fy = tex_y − y0 C00 = image[x0, y0] C10 = image[x0+1, y0] C01 = image[x0, y0+1] C11 = image[x0+1, y0+1] top = lerp(C00, C10, fx) bottom = lerp(C01, C11, fx) result = lerp(top, bottom, fy)

3 次 lerp。GPU 的 texture2D 里如果 filter = LINEAR，硬件替你做的就是这个。

Mipmap：预算好的多层降采样金字塔 Level 0 : 原图 (1024×1024) Level 1 : 512×512 ← 每 2×2 平均 Level 2 : 256×256 ... Level 10: 1×1 采样时选合适的 level（根据 screen-space 覆盖度）， 再做 trilinear（在两个相邻 level 之间也 lerp）。

缩得越小选越靠上的 level。这是消除 moire 的正确方法，但代价是 1.33× 内存（几何级数和）。WhatsCanvas 的 ImageSampling::MIPMAP_LINEAR 就是它。

13 · 光照数学

Lambertian + Phong：3D 里的两条基础光照公式

一个球体在旋转光源下的阴影。左：只有 diffuse (Lambertian) — 表面看起来"哑光"。中：加上 specular (Phong) — 表面出现高光反射，看起来"有光泽"。右：光源方向指示器。

Lambertian（漫反射） I_diffuse = max(0, N · L) × I_light × color N : 表面法向量（单位向量） L : 指向光源的向量（单位向量） N · L : 两个单位向量的点积 = cos(夹角) N · L = 1 → 正面对光（最亮） N · L = 0 → 表面平行光线（暗） N · L < 0 → 光在背面（clamp 到 0）

这就是"点积 = cos 夹角"最经典的用途。光线从法线方向来 → 全亮；斜着来 → 按 cos(θ) 变暗。

Phong specular（镜面反射） R = reflect(−L, N) // L 的反射向量 V : 指向摄像机的方向 I_specular = max(0, R · V)^shininess × I_light shininess 越大 → 高光越小越锐利 8 → 塑料 32 → 抛光金属 128 → 镜面

又是点积！R · V 的 shininess 次幂让高光集中在"完美镜面反射方向"附近。Phong 1975 年的博士论文。

完整 Phong 光照模型 I = I_ambient + I_diffuse + I_specular I_ambient : 环境光（常数，模拟四面反射的散光） I_diffuse : 表面漫反射（Lambertian） I_specular : 表面镜面反射（Phong）

3D 图形学的 hello world。现代 PBR (Physically-Based Rendering) 用更复杂的模型，但直觉全在这三项里。

14 · 数值精度

浮点数是骗子：为什么 0.1 + 0.2 ≠ 0.3

左：float32（GPU 默认）的"齿轮"——每个可表示的数之间有一定间距。当你把两个大的数相减，间距被暴露出来。中：0.1 + 0.2 的字面结果（0.30000000000000004）。右：在渲染里最常见的踩坑：远处顶点的 z 值分辨率崩溃（zfighting）。

float32 精度 32 位 = 1 符号 + 8 指数 + 23 尾数 可表示的相邻数间距 ≈ 值 × 2⁻²³ 在 1.0 附近：间距 ≈ 1.19e−7 在 10.0 附近：间距 ≈ 1.19e−6 在 1e6 附近：间距 ≈ 0.12 ← 已经很大！

远处的顶点 z 值分辨率崩溃 → z-fighting（两个物体表面在深度测试里争斗）。GPU 的解决办法：reverse-Z + logarithmic depth。

别用 == 比较浮点 // 错 if (a == b) { ... } // 相对精度 if (abs(a − b) < max(abs(a), abs(b)) × 1e−6) { ... } // 绝对精度（对小数字有效） if (abs(a − b) < 1e−7) { ... } // 混合（推荐） if (abs(a − b) < max(abs(a), abs(b), 1) × 1e−6) { ... }

写光栅器时，"面积 ≈ 0"要用 fabs(area) < 1e-7——WhatsCanvas rasterizeTriangles 里就是这么写的。

GLSL 精度限定 // 桌面 GL：默认 highp (float32) uniform vec2 pos; // GLES / WebGL 2： precision mediump float; // float16, 快，坐标容易崩 precision highp float; // float32, 慢，正确 // 手机 GPU 上有的 mediump 只是 float10 → 更糟

"手机上显示对但桌面上错"这类 bug 常常是 mediump 惹的祸。屏幕坐标 uniforms、深度、时间永远用 highp。

典型踩坑：
• 圆的边缘看起来"抖"：距离用 float32 算，本身有噪声。要么半径大一点，要么用 SDF。
• 阴影"贴不上"（Peter-Panning）：float32 深度不够，光源附近偏移几个像素。
• 大世界 z-fighting：可以在 shader 里做 gl_Position.z = log(...)。
• accumulate 时精度丢失：改用双精度 CPU 累加，最后一次转 float32 上传。
15 · 主流库怎么用这些数学

WhatsCanvas / Skia / Cairo / Qt / 浏览器 Canvas 各自的选择

WhatsCanvas

向量 & 矩阵用 glm（glm::mat4）；SDF 只用于 shader-based 效果；重心坐标手写在 SoftwareRenderer::rasterizeTriangles 里；Bezier flatten 在 Path 层完成。

Skia

SkMatrix（3×3）+ SkMatrix44（4×4）。SkPath 支持 conic 曲线（有权重的二次 Bezier），flatten 用递归 subdivision。SDF 仅用于 special-purpose text。

Cairo

cairo_matrix_t（3×3，含 xy/yx 剪切分量）。cairo_path_fixed_t 里 Bezier 用 16.16 定点数。CPU 光栅是扫描线 + 覆盖度，不用 barycentric。

Qt / QPainter

QTransform（3×3 affine + 透视）。Bezier flatten 用递归 + 曲率阈值。矩阵在 QOpenGLPaintEngine 里升到 4×4 做 GL 提交。

浏览器 Canvas 2D

API 层用 DOMMatrix（可 2×3 也可 4×4）。setTransform(a, b, c, d, e, f) 就是 3×3 齐次矩阵的 6 个独立分量。

3D 图形（Unreal / Unity / Blender）

4×4 是标配。渐变 / 距离场 / 重心坐标全部搬到 3D，公式基本不变——只是加了 z 维和透视除法。学会 2D 里的数学 → 3D 只是"多一维"。

共同点：齐次坐标 + 3×3/4×4 矩阵是通用语言，Bezier + flatten 是路径的通用做法，barycentric 是三角形插值的通用做法。这些几十年没变。
差异点：SDF 用在哪儿差异最大 —— 有的库只用于文字（Slug / MSDF）；有的用于所有 2D 元素（Rive / Signal）；WhatsCanvas 保持"几何 + coverage"，SDF 是补充手段。
16 · 学习建议

如果你想深入，从哪儿看起？

先掌握向量和点/叉积基础 90% 的 2D 图形代码都在做"向量差、点积、叉积"。理解它们等于理解一半 API 底层。
再理解 3×3/4×4 齐次矩阵进阶 "translate 也是矩阵乘法"是初学者最大的觉醒点。之后所有 canvas.translate/rotate/scale 都变得透明。
Bezier + flatten + de Casteljau路径 如果你想写字体渲染、SVG 解析、矢量编辑器——这是绕不开的。
SDFshader 时代 现代 UI 库（Rive、Compose、SwiftUI）越来越多把 2D 元素做成 SDF，因为 GPU 上非常便宜。
barycentric通用工具 三角形里做任何"顶点属性 → 像素属性"的插值。理解了这个，你会觉得所有 fragment shader 都变简单。
一句话总结 2D 图形库不是"神秘的黑盒"， 它就是几百年前的数学 + 现代硬件的组合。 向量、矩阵、Bezier、SDF、barycentric —— 掌握这五样，你可以从头写一个 2D 引擎。

这也是为什么 CS 课上学的东西看似"没用"——直到有一天你想画个圆角按钮的动画，才发现每一步都是它们。
