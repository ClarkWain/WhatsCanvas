后处理：从 3D 结果到最终照片的最后一公里

场景 render 结束只是"素材拿到了"。后处理管线（Post-processing pipeline）负责把 HDR 线性颜色变成一张能上屏的、有电影感的照片：Bloom 制造柔光晕、Tonemap 把 100 nits 压到 SDR、Color Grading 定情绪、Vignette 引导视线、Motion Blur/DOF 补相机语言、最后 FXAA/SMAA 抹掉几何锯齿。这个教程会带你看清每一步做什么、公式是什么、为什么这个顺序不能乱。

1. HDR 是前提Bloom / Tonemap 都在 linear HDR 空间做，最后一 pass 才转 sRGB。
2. 顺序决定质感先 Bloom 再 Tonemap，还是反过来？先 DOF 再 Motion Blur？都有 canonical answer。

01 · HDR & linear space

后处理为什么必须在 HDR / linear 空间做

普通显示是 sRGB gamma-encoded 8-bit（0..255，非线性）。后处理里做 blur / add / multiply → 都是线性运算，只有在线性空间做才物理正确。而"超白"（亮度 > 1，如太阳、金属高光）必须用 float16/32 HDR buffer 存下来——8-bit 一压就 clamp 到 1.0，Bloom 就没得算了。

左：LDR 8-bit 缓冲，超过 1 的部分被截断成白，视觉上光源就是一块死白；右：HDR float 缓冲，保留超 1 亮度信息，Bloom 才能算出"透光光晕"。

sRGB ↔ linear
linear = (sRGB / 255)^2.2 (approximate) sRGB = 255 · linear^(1/2.2) (approximate) 准确公式带线性段，见 canvas-math 教程 07。

硬件支持自动转换：GL_SRGB8_ALPHA8 纹理采样时自动 sRGB→linear；GL_FRAMEBUFFER_SRGB 让 shader 输出 linear，写入时自动 linear→sRGB。做后处理时一定要用这两个开关。

常见 buffer 格式：HDR scene color 用 R11G11B10_FLOAT（省 25% 带宽）或 RGBA16F；depth 用 D24S8；motion vector 用 RG16F。
02 · Bloom（辉光）

下采样金字塔 + 上采样合成

Bloom 模拟镜头/眼睛遇强光时的散射晕光。核心思路：把 HDR 图 threshold（截取亮部）→ 逐级下采样构建金字塔（1/2, 1/4, 1/8, 1/16...）→ 每级做一次高斯模糊 → 反过来一层层上采样加回主图。为什么金字塔？直接对全分辨率做大半径高斯太贵；下采样后小半径就能覆盖同样的视觉范围。

左上：原始 HDR；右下：加了 Bloom 之后。中间可视化 4 级金字塔（依次显示 1/2, 1/4, 1/8, 1/16 分辨率的模糊亮部）——这就是 Bloom 的中间产物。

模糊算法选型

  • 可分离高斯 (Separable Gaussian)：横一次 + 竖一次，代价 O(2n) 而非 O(n²)。质量高、速度中。
  • Kawase blur：4 tap sampling with growing offset，视觉上接近高斯但每 pass 极便宜。手游标配。
  • Dual Filtering (Marius Bjørge)：下采样时 average 4 tap、上采样时 add 8 tap。UE / Unity Bloom 都用类似。
Threshold 曲线
// 硬 threshold 会有 popping bright = max(0, luminance - threshold) / luminance · color // 软 threshold (Karis 2013) knee = threshold · 0.5 soft = clamp(brightness - threshold + knee, 0, 2·knee) soft = soft² / (4·knee + 1e-4) bright = max(soft, brightness - threshold) / max(brightness, 1e-4) · color
03 · Tonemap

Reinhard / ACES / AgX：把 HDR 压回 SDR

渲染出的 HDR 值可能是 0..100+，显示器只能显示 0..1（SDR）。Tonemap 就是一个 float → float 曲线，把 HDR 压到 [0,1]，暗部保留细节、亮部平缓 rolloff、饱和高光有电影感。三大主流：Reinhard（老、平淡）、ACES（Filmic，行业标准）、AgX（2023 新起、Blender 4.0 默认）。

上：色阶从 0 到 8（HDR）的连续图；下：各 tonemap 曲线（input → output）。Reinhard 快压快平；ACES 中段肩曲柔和；AgX 亮部保留最多色相，不会过曝成白。

三种数学
Reinhard: y = x / (1 + x) ACES: y = clamp((x·(2.51x + 0.03)) / (x·(2.43x + 0.59) + 0.14), 0, 1) AgX: 更复杂，log 域 sigmoid + 色相恢复矩阵

Reinhard 简单但饱和色会往灰去，Blender 早期版本；ACES 是 Academy Color Encoding System 的显示 transform，几乎所有 3A 引擎默认；AgX 特点：亮部不掉色（rgb 独立 tonemap 会让红色高光变粉，AgX 保持红）。

曝光要放在 tonemap 之前 
vec3 hdr = texture(sceneColor, uv).rgb;
hdr *= exp2(exposureEV);   // 曝光调整
vec3 sdr = ACESFilmic(hdr); // tonemap
gl_FragColor = vec4(pow(sdr, vec3(1.0/2.2)), 1.0); // linear→sRGB

如果 tonemap 之后再乘曝光 → 已经 clamp 过的值再乘，暗部提亮无效。

04 · Color grading & LUT

用一张 3D 立方体决定整个电影的色调

调色师用 DaVinci Resolve 把中性场景调成"科幻蓝调"或"暖橘落日"，最终把这个映射 bake 成一张 3D LUT（例如 32³ 或 64³ 颜色立方体）。shader 里以 tonemapped color (RGB in [0,1]) 作为 3D 纹理坐标采样即得成品色。

同一张色板 + 参考照片，套用不同 LUT。Teal & Orange 是好莱坞 90% 剧情片配色（阴影蓝绿、肤色暖橘）——观众看惯了，但技术上就是一个查表。

3D LUT 采样 shader 
uniform sampler3D lutTex;      // 32³ or 64³
uniform float lutSize;         // 32.0 or 64.0

vec3 applyLUT(vec3 c) {
    // trilinear sample; hardware 3D texture 自动做
    vec3 scale = vec3((lutSize - 1.0) / lutSize);
    vec3 offset = vec3(0.5 / lutSize);
    return texture(lutTex, c * scale + offset).rgb;
}

工业上常把 3D LUT flatten 成 2D strip（32×1024 slices），用 sampler2D 采样——支持性更广（老手机不好 3D 纹理）。

LUT 顺序：必须放在 tonemap 之后（LUT 假设输入是 SDR [0,1]）、放在色差/vignette 之前（这些是画面特效，不该被 LUT 校调）。
05 · Vignette / CA / Film grain

三个补丁效果，模拟真实相机

数字渲染太完美了——反而不像"电影"。加一点 vignette（暗角，引导视线到中心）+ chromatic aberration（色差，边缘 R/B 通道分离）+ film grain（细粒度噪声，破一破 banding）→ 立刻电影感。

数学
// Vignette d = length(uv - 0.5) vig = smoothstep(radius, radius - falloff, d) color *= vig // Chromatic Aberration uv_r = center + (uv - center) · (1 + strength) uv_b = center + (uv - center) · (1 - strength) final.r = sample(uv_r).r final.b = sample(uv_b).b final.g = sample(uv).g // Film Grain n = hash(uv + time) color = mix(color, vec3(n), amount)
06 · Motion blur & DOF

相机语言：动感与焦点

Motion blur：用 velocity buffer 沿运动方向 sample 8~16 次并平均，快门时间越长模糊越强；Depth of Field：根据 depth 与焦距差计算 CoC (circle of confusion) 半径，散景是圆盘/六边形 bokeh，模拟光圈叶片形状。

场景：3 个球在不同 z，横向运动。左：无后处理；右：motion blur + DOF。当焦距对准中球，前后球自然虚化，正在动的球带出运动方向的尾迹。

CoC 公式
// depth of field CoC = |1/depth − 1/focal_dist| · aperture · f CoC = clamp(CoC, 0, maxRadius) // Bokeh kernel = disc / hexagon shaped weighted average

分层 DOF（near/mid/far）比全屏卷积更快：不同 CoC 半径的像素放不同 tile，卷积核大小对齐 CoC。

顺序：DOF 应该在 tonemap 之前（还在 HDR，散景亮点不被压死）；motion blur 通常与 DOF 同一 pass 或紧接其后。
07 · FXAA / SMAA 空间抗锯齿

如果没上 TAA，得靠这些兜底

MSAA 内存开销大且对 deferred 不友好；TAA 需要 velocity buffer 和 history。FXAA (Fast Approx.) 和 SMAA (Subpixel Morphological) 是两种纯 shader、单帧、只吃 color buffer 的空间抗锯齿。质量：SMAA > FXAA >> nothing；成本：FXAA < SMAA。

同样的斜边缘，FXAA 用 luma 梯度检测 + 沿边模糊；SMAA 检测出边缘图案（L 型、Z 型、U 型）后精准恢复原始边缘。

三步 FXAA 简版

  1. 估计当前像素的 luma & 4 邻域 luma；
  2. 如果对比度 < 阈值 → 早退出（平坦区不动）；
  3. 找出梯度方向 → 沿该方向 sample 一系列点直到发现"另一侧"→ 混合。

SMAA 三 pass：edge detection → blending weight → neighborhood blending。开源实现 iryoku/smaa。

08 · 完整管线组织

把所有 pass 串起来

一个典型 AAA 后处理管线大约有 10~20 pass。次序不能乱：HDR-space 的（Bloom / DOF）→ Tonemap → SDR-space 的（LUT / Vignette / CA / AA）→ 输出。所有 pass 都是"渲染一个全屏三角形"（大小 = 屏幕），vertex shader 只是过一下 uv。

全屏三角形技巧
// 一个覆盖全屏的三角形（而非 quad） positions[3] = { (-1,-1), (3,-1), (-1,3) }; // GPU 会自动裁掉屏外部分 // 好处：单个三角形无对角线接缝、shader 调度更规整
