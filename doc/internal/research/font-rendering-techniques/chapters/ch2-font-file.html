字字体渲染原理
CHAPTER 02 · INSIDE A FONT

一个字体文件里到底装了什么

很多人以为 .ttf 里存的是一张张字母图片。其实它更像一个 数据库：由若干张「表（table）」组成，每张表负责一件事—— 有的存轮廓，有的存映射，有的存排版规则。这一章我们就把它拆开看看。

字体文件 = 一叠表

一个 TrueType / OpenType 文件，开头是一份表目录（table directory）， 就像一本书的目录：记录每张表叫什么、在文件的哪个字节位置、有多大。 渲染器需要哪张表，就按目录跳过去读哪张。结构大致长这样： 

MyFont.ttf
├─ sfnt header        // 文件类型 + 表数量
├─ table directory   // 目录：每张表的 名字 / 偏移 / 长度
└─ tables
   ├─ cmap   字符 → 字形索引的映射
   ├─ glyf   字形的轮廓（贝塞尔曲线）
   ├─ hmtx   每个字形的宽度等度量
   ├─ head   字体头：em 大小、边界框…
   ├─ GSUB   连字 / 上下文替换
   ├─ GPOS   字偶距 / 精确定位
   ├─ name   字体名称、版权
   └─ EBDT   内嵌位图 / 彩色字形

观察 这些表在渲染流水线里是分阶段被用到的：先用 cmap 找字形索引 → 用 GSUB/GPOS 塑形 → 用 glyf 取轮廓 → 用 hmtx 定位。 本教程后续几乎每一章，其实都是在深入讲其中某几张表。

字体族、字体面、样式是什么关系

在代码里写 font-family: Inter 或 Paint::setFontFamily("Inter") 时， 你指定的通常不是一个具体文件，而是一个字体族（font family）。 一个 family 下面会有多张具体的字体面（font face），例如 Regular、Bold、Italic。 渲染器要根据 family、weight、slant/style 去挑出最合适的 face。

概念含义例子
Font family
字体族		一组设计风格一致的字体集合，是 API 里最常指定的名字。Inter、Roboto、Noto Sans CJK
Font face
字体面		family 里的某一个具体样式，通常对应一个文件或 TTC 里的一个 face index。Inter Regular、Inter Bold、Inter Italic
Weight
字重		笔画粗细，常用 100-900 表示。400 = Regular，700 = Bold
Slant / Style
倾斜/样式		正体、斜体或倾斜体；真斜体通常是重新设计的字形，伪斜体只是几何倾斜。normal、italic、oblique
Collection index
集合索引		.ttc / .otc 一个文件里装多个 face，需要 index 指定取哪一个。PingFang.ttc 里的不同字重/区域 face
Inter                  // font family
├─ Inter-Regular.ttf   // face: weight 400, slant normal
├─ Inter-Bold.ttf      // face: weight 700, slant normal
├─ Inter-Italic.ttf    // face: weight 400, slant italic
└─ Inter-BoldItalic.ttf// face: weight 700, slant italic
为什么这件事会影响渲染
同一个 family 下，不同 face 的字形轮廓、度量、kerning、OpenType feature 都可能不同。 所以“用粗体”不只是把像素描粗一点；正确做法是先匹配到 Bold face，再用它自己的 cmap、GSUB/GPOS、glyf 和 hmtx 参与后续渲染。

那「字形」到底是什么

刚才反复出现了三个词：cmap 里被映射的叫「字符」，glyf 里存的叫「字形」， EBDT 里存的叫「位图」。它们天天被混用，但其实是三个不同层次的东西。 分清楚它们，后面所有内容就都顺了。

名词是什么住在哪张表例子
字符 Character抽象文字，Unicode 码点，存储单位cmap 的输入U+0041 = A
字形 Glyph字体里一个具体形状，显示单位glyf / CFF这套字体里 A 的那条轮廓
位图 Bitmap字形在某字号下栅格化后的灰度方格临时生成（或 EBDT）16px 下 A 的覆盖率位图

它们之间是这样一条单向链路——每一步都「多对一」或「一对多」，所以三者数量并不相等：

字符 U+0041 —cmap→ 字形 #36 (A的轮廓) —栅格化→ 位图 16px / 32px / …
一句话记住 字符 ≠ 字形 ≠ 位图。一个字符可能对应多个字形，多个字符也可能合并成一个字形（连字）； 而一个字形在不同字号下，又对应无数张不同的位图。

为什么会出现「豆腐块」 如果某个字符在 cmap 里查不到，就会得到字形索引 0（.notdef）， 也就是常见的 □。这通常意味着当前字体里没有这个字——系统会尝试「字体回退」去别的字体里找。 下一章我们专门讲这个查找与回退过程。
检查一下理解 ✅

问：把字号从 16px 改成 32px，字体文件里 glyf 表中的轮廓数据会变吗？

看答案

不会。轮廓是与分辨率无关的曲线，永远不变。变的只是渲染时的缩放系数， 以及最终栅格化出来的位图。字号只影响「怎么画」，不影响「文件里存了什么」。
