SDF / MSDF：让一张小图任意缩放

第 10 章留了个尾巴：普通字形图集是「按某个字号烤死」的，放大就糊。要让一张小纹理也能任意放大还保持锐利边缘，业界的答案是有向距离场（SDF），以及它的升级版 MSDF。这一章把原理讲透，并配可交互演示。

先看问题：图集放大就糊

图集纹理里存的是像素的明暗。GPU 放大时只能在这些像素之间做双线性插值——边缘会被「抹开」成一片灰，于是发虚、发糊。字号放得越大越明显。要解决它，得换一种存储内容。

核心思想：别存像素，存「到边缘的距离」

SDF（Signed Distance Field，有向距离场）不存「这个像素是黑是白」，而存「这个像素到字形轮廓的最近距离」：在字形内部距离为正、外部为负、正好在边缘上为 0。

渲染时，着色器对这张距离图做双线性插值（距离插值是平滑且线性的，不像明暗那样一抹就糊），再判断：距离 ≥ 0 就是字内、上色；< 0 就是字外、透明。无论放多大，「距离 = 0 的那条线」始终能算得清清楚楚，边缘自然锐利。

但「存像素」和「存距离」到底差在哪？一图胜千言——下面左边是存像素（每格只有黑/白两种值），右边是存距离（每格是一个「到边缘有多远」的数值，用颜色表示：蓝=字外、白=边缘、橙=字内）。拖动滑块选一行，看最下方那行数值在放大插值时各自会怎样。

关键就在这条扫描线（两图中的蓝框行）：存像素是 0/1 的阶跃——放大时在 1 和 0 之间插值，必然经过一片 0.5 左右的灰带（即边缘发糊，灰带还随放大变宽）；存距离是一条平滑斜线，无论放多大，「＝ 0 的那一点」（绿虚线）位置精确不动，卡这条线就得到锐利边缘。

SDF 的软肋：尖角会被磨圆

单通道 SDF 有个先天缺陷：它只记录「到最近边缘的距离」这一个标量。在字形的尖角处，距离场会像「等高线绕过山尖」一样把拐角抹圆——放大后本该锋利的尖角变成了小圆角。字号越大越明显，对衬线、尖锐的笔锋尤其伤。

MSDF：用「多通道」把尖角找回来
MSDF（Multi-channel SDF，多通道有向距离场）把距离场分别编码进纹理的 R / G / B 三个通道，每个通道负责轮廓的不同边。着色器取三者的中位数（median）作为最终距离。多个通道在拐角处「交叉」，正好把尖角的两条边都保住，于是放大也不圆。代价是生成更复杂（常用 msdfgen 库预处理）、纹理占 3 个通道。

顺带白送：描边、发光、阴影

因为 SDF 在每个像素都知道「离边缘多远」，很多效果几乎零成本：

效果在着色器里怎么做
抗锯齿在 距离=0 附近用 smoothstep 做一条柔和过渡带
加粗 / 变细把判定阈值从 0 改成 ±一点（上面滑块就是它）
描边距离在 [-w, 0] 的环形区域涂边框色
外发光 / 阴影对负距离区域按距离做渐隐，偏移一点就是阴影
SDF 不是万能
SDF/MSDF 适合会被缩放、需要特效的文字（游戏 UI、标题、3D 场景里的字）。但它不擅长极小字号的正文——小字号要的是 hinting、子像素这类「像素级精修」，SDF 在那个尺度反而不如直接按字号光栅化的图集清晰。CJK 上万字形做 MSDF 图集也很重。所以浏览器正文仍走 FreeType 直接光栅化，SDF 是「特定场景的利器」，不是替代品。
📌 一句话总结
SDF 把图集里存的「像素明暗」换成「到边缘的距离」，于是一张小图也能任意放大、还白送描边/发光；MSDF 用三通道取中位数把尖角救回来。代价是预生成更复杂、不适合极小正文——它是缩放与特效场景的利器。
检查一下理解 ✅

问：SDF 为什么放大不糊，而普通点阵图集放大会糊？

看答案

点阵图集存的是像素明暗，放大时在明暗之间插值，边缘被抹成一片灰 → 糊。SDF 存的是到边缘的距离，距离插值是平滑线性的；着色器只要找「距离 = 0」那条线就能重新算出锐利边缘，与放大倍数无关。代价是单通道 SDF 会把尖角磨圆，需要 MSDF 用多通道中位数来修。
