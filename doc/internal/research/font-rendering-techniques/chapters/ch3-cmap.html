字字体渲染原理
CHAPTER 03 · CHARACTER TO GLYPH

字符到字形：cmap 是怎么查的

你按下键盘的「永」，存进文件的是码点 U+6C38；但字体里画的那一笔，叫字形 #1234。这两者之间隔着一张查找表——cmap。这一章把这张表彻底拆开。

先分清两个东西：码点 ≠ 字形索引

这是整章的基石，务必分清：

code point · 码点
U+6C38

Unicode 给每个抽象字符分配的唯一编号，表示「这是『永』这个字」。它跟用哪个字体无关——换成宋体、黑体，码点都是 U+6C38。

glyph index · 字形索引
#1234

这个字在当前这个字体文件里排第几个图形。同一个「永」，在宋体里可能是 #1234，在黑体里是 #5678。它只在本字体内有意义。

一句话记住
码点回答「这是哪个字」（身份），字形索引回答「在这个字体里画哪一幅图」（位置）。cmap 表就是把前者翻译成后者的字典。

动手查一次：字符 → 码点 → 字形索引

cmap.lookup

cmap 内部长什么样：分段映射

字体不可能为每个码点都存一行（Unicode 有十几万码点）。cmap 用分段（segment）压缩：把连续的码点段映射到连续的字形索引段，只存「段的起止 + 偏移」。最常用的是 format 4（覆盖基本多文种平面 BMP）和 format 12（覆盖全部 Unicode，含 emoji、扩展汉字）。

cmap.segments

每一段记的是 [起始码点, 结束码点] → 字形索引偏移。查 U+0043('C') 时，先二分找到它落在哪一段，再用 字形索引 = 码点 − 段起点 + 偏移 算出结果。这样几十万码点只用几百段就能表达，查找还是 O(log n)。

查不到怎么办：.notdef 与字体回退

如果 cmap 里没有这个码点，会发生两件事中的一件：

  • 字形索引 0 = .notdef：每个字体的第 0 号字形固定是「缺字符」图形，通常是一个空心方框 □，俗称豆腐块（tofu）。
  • 字体回退（font fallback）：操作系统/浏览器发现当前字体没有这个字，会去候选字体列表里换一个有的字体来画——所以一句话里可能混着好几个字体。

「名字里有生僻字显示成方框」「emoji 在老系统变空框」，本质都是：码点存在，但当前字体的 cmap 查不到对应字形，又没有可回退的字体。

插曲：汉字编码的演进，与「打不出的名字」

对汉字来说，「查不到字」不只是字体问题，背后还有一段编码扩容史。计算机最早只为英文设计，汉字要先有一套「码」才能进电脑——而这套码能装下多少字，直接决定了哪些字「打得出、显示得了」。

编码标准年代收录汉字量解决 / 遗留
GB23121980约 6763 个覆盖日常用字，但大量生僻字、繁体字、人名地名用字打不出
GBK1995约 21886 个兼容 GB2312，补入繁体字和更多汉字，缓解但未根治
GB180302000 / 2005 / 2022覆盖全部 Unicode CJK国家强制标准，用 1/2/4 字节变长编码，收录少数民族文字
Unicode CJK1993 至今已超 9.8 万 个统一全球文字；汉字仍在「扩展区」不断新增
那些「打不出的名字」
早年用 GB2312 录入系统时，有人名里带生僻字（如「𬬮」「龘」「煊」中的某些），系统里根本没有这个码，于是户籍、银行、机票系统只能用同音字、拼音甚至 ? 代替——这是真实困扰过很多人的麻烦。随着 GBK → GB18030 → Unicode 一路扩容，能「编码」的字越来越多，这个问题大为缓解。
编码有了，字体不一定有
注意「能编码」和「能显示」是两回事。Unicode 收了近 10 万汉字，但一个字体文件通常只画了其中 2–7 万个（常用字 + 次常用字）。遇到特别生僻的字（多在 CJK 扩展 B/C/D/E/F 区），即使码点合法、能存进电脑，字体里没有对应字形，照样显示成豆腐块 □。这时只能换装一个收录更全的「大字库」字体（如部分思源字体、方正超大字符集），或靠系统字体回退。
cmap 之后还没完
cmap 给出的只是初步字形索引。接下来塑形（第 4 章）还会把它们替换/重排：连字会把两个字形并一个，阿拉伯字母会按位置换成不同形态。所以「码点序列 → cmap → 字形序列」只是第一步，不是最终上屏的字形。
检查一下理解 ✅

问：同一个汉字「永」，在宋体和黑体里的「码点」和「字形索引」分别一样吗？

看答案

码点一样（都是 U+6C38，由 Unicode 决定，与字体无关）；字形索引通常不一样（每个字体内部字形的排列顺序不同，宋体里可能是 #1234，黑体里是 #5678）。这正是为什么字形索引「只在本字体内有意义」。
