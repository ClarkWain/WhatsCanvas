互动教学 · 混合模式 (Blend Modes)

两块颜色相遇的时候，你希望发生什么？

"透明图层压在另一张图上"看起来只是一个视觉问题，其实是数学问题：新颜色 = f(源颜色, 目标颜色)。混合模式就是这个 f 的一整套约定俗成的选项——从最普通的"上面盖住下面"（SRC_OVER），到"只留下重叠部分"（SRC_IN），再到 Photoshop 里那些花哨的 MULTIPLY / SCREEN。这个教程会带你看清：每一种模式的公式、它在 GPU 上如何映射成 glBlendFuncSeparate、WhatsCanvas 里 14 种模式对应的实际参数，以及"什么时候用哪个"。

1. Porter-Duff（合成） 12 种基于 α 的"图层重叠"操作：SRC / DST / OVER / IN / OUT / ATOP / XOR ...
2. Separable（可分离） 基于每通道乘除的"美学"混合：MULTIPLY / SCREEN / ADD 等。

这页要带你掌握的 5 件事

  • 预乘 alpha（premultiplied）是所有混合公式的前提，为什么？
  • SRC_OVER 是怎么从"你选择每层颜色的权重"推出来的。
  • Porter-Duff 12 种模式 = 用 (Fs, Fd) 两个系数拼出来的组合。
  • GPU 上是怎么用一次 glBlendFuncSeparate 表达全部 14 种模式的。
  • 什么场景该用 SRC_OVER / MULTIPLY / DST_IN，什么坑要避开。
01 · 先看基础

预乘 alpha 和"最普通的透明合成"到底怎么算

上图从左到右：目标色（背景）→ 半透明源色（Fs = 1, Fd = 1 − Sa 时的 SRC_OVER）→ 结果。α 从 0（完全透明，等于背景）滑到 1（完全不透明，等于源）。你会看到中间 alpha 值下，结果是"按 α 混合两种颜色"。

最朴素的公式：SRC_OVER C_out = C_src × α_src + C_dst × (1 − α_src) α_out = α_src + α_dst × (1 − α_src)

这就是"半透明贴纸压在另一张色纸上"的直觉：结果 = α 部分用源色 + (1−α) 部分用背景色。α_out 说明"两层叠起来后，整个像素还是透过多少下面的东西"。

预乘 alpha（premultiplied） 存储时把 RGB × α 一次算好： Cp_src = C_src × α_src Cp_dst = C_dst × α_dst 于是 SRC_OVER 就变成了： Cp_out = Cp_src + Cp_dst × (1 − α_src) α_out = α_src + α_dst × (1 − α_src)

好处：混合公式里不再有"× α"这一步。多次合成也不会累积精度损失。WhatsCanvas 和绝大多数 GPU 后端全程使用预乘 alpha。

GPU 的一般形式 C_out = Fs × C_src + Fd × C_dst α_out = Fs_α × α_src + Fd_α × α_dst Fs / Fd 是"源 / 目标的混合权重"， 每种混合模式就是选一组 (Fs, Fd)。

这就是 glBlendFuncSeparate(srcRGB, dstRGB, srcAlpha, dstAlpha) 的 4 个参数。它把"混合模式"抽象成了 4 个可选值。

03 · Separable 三兄弟

              
MULTIPLY / SCREEN / ADD：不是"合成"而是"美学"

            

          

          

            

              

                
                
                
                
                
              

              
              
和 Porter-Duff 不同，可分离（separable）混合逐通道做非线性运算：MULTIPLY 是相乘（"两色都亮才亮"），SCREEN 是反乘（"两色都暗才暗"），ADD 是相加（发光效果）。它们不能用一句"图层重叠"来描述——更像"Photoshop 图层模式"。

            

            

              

                MULTIPLY
                C_out = C_src × C_dst
GPU: glBlendFuncSeparate(GL_DST_COLOR, GL_ZERO, ...)
                
直观：白色 (1) × X = X，白色什么都不改；黑色 (0) × X = 0，黑色永远变黑。常用于"给底图增加阴影"——半透明黑色 MULTIPLY 就是压暗。

              

              

                SCREEN
                C_out = 1 − (1 − C_src) × (1 − C_dst)
GPU: glBlendFuncSeparate(GL_ONE, GL_ONE_MINUS_SRC_COLOR, ...)
                
就是"MULTIPLY 的对偶"。黑色 (0) 什么都不加，白色 (1) 全饱和。常用于"给底图加亮点、加高光、加发光"——SCREEN 白色圆 = 光晕。

              

              

                ADD
                C_out = C_src × α_src + C_dst
GPU: glBlendFuncSeparate(GL_SRC_ALPHA, GL_ONE, ...)
                
最粗暴：直接相加，允许"爆掉"（超过 1 被 clamp 到 1）。常用于粒子系统、火光、能量光柱、HDR 光晕。

              

              

                为什么它们是"可分离"？ 每个通道（R/G/B）独立计算，彼此不相干。对比 Hue / Saturation / Color 这些"HSL 模式"就要一起考虑 RGB 转 HSL 再合成——那些叫non-separable，WhatsCanvas 没实现，Skia 里也是单独一类。

05 · WhatsCanvas 内部

              
从 Paint::setBlendMode 到 glBlendFuncSeparate

            

          

          

            

              
1. Paint 层的枚举 —— include/wsc/Paint.h

              
enum class BlendMode {
    SRC_OVER,   // 默认。透明贴纸压在下面。
    SRC, DST, CLEAR,
    SRC_IN, DST_IN, SRC_OUT, DST_OUT,
    SRC_ATOP, DST_ATOP, XOR,
    ADD, MULTIPLY, SCREEN
};


              
2. Renderer 层：翻译成 GL 参数 —— src/render/RenderContext.cpp

              
switch (mode) {
case DrawBlendMode::SrcOver:
    glBlendFuncSeparate(GL_SRC_ALPHA, GL_ONE_MINUS_SRC_ALPHA,
                        GL_ONE, GL_ONE_MINUS_SRC_ALPHA);
    break;
case DrawBlendMode::Multiply:
    glBlendFuncSeparate(GL_DST_COLOR, GL_ZERO,
                        GL_DST_ALPHA, GL_ZERO);
    break;
case DrawBlendMode::Screen:
    glBlendFuncSeparate(GL_ONE, GL_ONE_MINUS_SRC_COLOR,
                        GL_ONE, GL_ONE_MINUS_SRC_ALPHA);
    break;
// ...其余 11 种模式类似...
}


              
3. Software 后端：CPU 里手算同一套公式 —— src/render/software/SoftwareRenderer.cpp

              
inline void blendPixel(uint8_t *dst,
    float sr, float sg, float sb, float sa,
    DrawBlendMode mode)
{
  if (mode == DrawBlendMode::SrcOver) {
    // 预乘 alpha 下的公式：out = src + dst × (1 − sa)
    const float inv = 1.0f - sa;
    const float dr = dst[0] / 255.0f;
    // ...
    dst[0] = toByte(sr * sa + dr * inv);
    dst[1] = toByte(sg * sa + dg * inv);
    dst[2] = toByte(sb * sa + db * inv);
    dst[3] = toByte(sa + da * inv);
    return;
  }
  // ...其余 13 种模式...
}

              
这就是"跨后端 pixel-parity"的关键：Software 和 OpenGL 用同一批数学公式，只是一个用 CPU 手算、一个用 GPU 硬件混合。任何微小差异（如整型舍入方向、gamma 空间选择）都会通过 parity_probe 抓出来。

            

            

              

                1. 用户 API
                Paint p; p.setBlendMode(Paint::BlendMode::MULTIPLY); canvas.drawCircle(..., p);
              

              

                2. 命令编码
                DrawPathData::blendMode = toDrawBlendMode(paint.getBlendMode()); 每条命令都带 blend 状态。
              

              

                3. Renderer 状态设置
                context.applyBlendMode(mode)：一次 glBlendFuncSeparate。合批时会把同 blend mode 的连续 draw 合并，减少状态切换。
              

              

                4. 后端提交
                GL：硬件混合器直接算；Software：CPU 每像素调 blendPixel；Vulkan/Metal 里 pipeline state 里预先烘好 blend attachment。
              

              

                1.2.1 相关：本分支的 parity_probe 里包含全部 11 种 blend 模式验证，Software vs OpenGL 全部 max delta ≤ 1（见 栅格化与缓存 教程的 section 06 和 examples/parity_probe/main.cpp）。
              

            

          

        


        
        

          

            

              
06 · 典型场景

              
哪个模式做什么用？看 4 个真实例子

            

          

          

            

              UI 绘制 · SRC_OVER
              
按钮、图标、文字。默认模式就是它，几乎所有 drawXxx 都走这条路径。

            

            

              形状裁剪 · SRC_IN / DST_IN
              
把一张纹理裁剪成任意形状：先画形状（作 mask），再用 DST_IN 画图片。

            

            

              光效 / 阴影 · MULTIPLY / SCREEN / ADD
              
粒子系统、发光边、阴影层。选 MULTIPLY 压暗、SCREEN 提亮、ADD 曝光。

            

            

              擦除 · CLEAR / DST_OUT
              
橡皮擦、透明打洞。saveLayer 内画一个 CLEAR 模式的圆，就是"在层上挖洞"。

            

          

          

            
UI 绘制 · SRC_OVER

            
这是最常用的模式，所有 Paint 的默认值就是 SRC_OVER。你调 canvas.drawRect / drawText / drawImage 时如果不改 blend，走的就是它。它保证"新画的东西压在旧的上面，尊重 α 透明度"。

      07 · 主流做法
      
              
      Skia、Cairo、Qt、浏览器 Canvas 都有什么 blend
      
            
      
          
      
          
      
            
      
              Skia
              
      SkBlendMode 30+ 种：Porter-Duff 12 + separable + non-separable（Hue/Saturation/Color/Luminosity）。GPU 端能用固定管线的走硬件混合，其他走 shader-based blending。
      
            
      
            
      
              Cairo
              
      cairo_operator_t 30+ 种，覆盖 Porter-Duff 全集 + separable + 少量 HSL。CPU 光栅器直接实现，性能上和 shader-based 差别不大。
      
            
      
            
      
              Qt / QPainter
              
      QPainter::CompositionMode 20+ 种。软件后端手算；OpenGL 后端能映射到硬件的走 glBlendFuncSeparate，剩下的用 shader 或 FBO trick。
      
            
      
            
      
              浏览器 Canvas 2D
              
      globalCompositeOperation 25 种，命名是 CSS 风格："source-over" / "multiply" / "difference" 等。底下是 Skia / CoreGraphics 实现。
      
            
      
            
      
              CSS mix-blend-mode
              
      不是 Canvas 而是 CSS 层的合成。类似 Skia 的可分离 + non-separable 集合。这也是为什么 Chrome 用 Skia 后端能"零成本"支持 CSS blend mode。
      
            
      
            
      
              Metal / Vulkan
              
      硬件层面只提供固定管线的 blendAttachment（Porter-Duff + separable）。要 non-separable HSL 只能自己写 shader + sample 上一层 FBO。
      
            
      
          
      
          
      
            
      共同点：所有库都把 Porter-Duff 12 兄弟 + separable 3-5 种当作"标配"。这是硬件混合器能直接支持的最大集合。
      
            
      差异点：WhatsCanvas 只实现 14 种（Porter-Duff 11 + separable 3）——够 UI + 普通图形效果，不追求 Photoshop 全集。想要 HSL 混合需要自己上 saveLayer + shader-based 实现。
      
          
      
        
      

        
        
      
          
      
            
      
              
      08 · 你可以怎么判断
      
              
      选混合模式的 4 条经验
      
            
      
          
      
          
      
            
      
              
      没想清楚就用 SRC_OVER默认 90% 的 UI / 图片 / 文本绘制都是它。选错了别的模式，多半是把简单问题复杂化。
      
              
      做 mask / 挖形状 → DST_IN / SRC_IN配合 saveLayer "把图像裁成圆形头像"、"把渐变裁成文字形状"都是这条路。关键：这些模式只在 saveLayer 里才有可预测的效果，因为它们要求目标层已经画好了 mask。
      
              
      发光 / 火焰 / 粒子 → ADD要小心 HDR ADD 会让颜色"爆掉"（超过 1）。想要软饱和用 SCREEN；想要柔和加亮用半透明 SRC_OVER 白色。
      
              
      压暗 / 阴影 → MULTIPLY别忘 α MULTIPLY 全屏黑色 = 直接变全黑（0 × X = 0）。要"轻微压暗"，用半透明黑色 SRC_OVER，或者浅灰MULTIPLY。
      
              
      擦除 / 打洞 → CLEAR + saveLayer易踩坑 CLEAR 不 saveLayer 直接画会把整个像素变透明（包括下面所有内容）。做"层内打洞"必须先 saveLayer，画完 restore。
      
            
      
            
      
              一句话总结
              混合模式 = 选一组 (Fs, Fd) 权重。
Porter-Duff 12 个基于 α 的组合覆盖了"合成"意图；
Separable 3-5 个基于颜色的组合覆盖了"美学"意图。
选错了不是崩溃，是"看起来不对"——所以直觉比公式更重要。
              
      下次画不出想要的效果时，先问："我是想合成图层，还是想让颜色变亮 / 变暗？" 这个二分决定了你该找 Porter-Duff 还是 Separable。
