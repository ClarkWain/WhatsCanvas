互动教学 · 离屏渲染

什么是"离屏"？画布画在哪儿，我们又怎么把它取出来？

离屏渲染（off-screen rendering）不是一个专门的技术，而是一整套"把绘制目标从窗口拿走"的思路：结果不进屏幕，而是进一个缓冲区，供你读回像素、当纹理、或延后合成到别的画面。这个教程会用交互演示带你看清：为什么要用离屏、Software 和 OpenGL 后端各自怎么做、WhatsCanvas 的 OutputTarget 分为哪几种，以及主流库的取舍。

1. 先理解"目标" 绘制命令的终点不总是屏幕，可以是 CPU RGBA、GPU 纹理、共享 framebuffer。
2. 再看代价 CPU 离屏几乎零成本；GPU 离屏需要 FBO + 纹理 + 上下文，往返有代价。

这页要带你掌握的 4 件事

  • "离屏"到底渲染到哪里，为什么它比"直接画到窗口"多出一步。
  • 4 种典型场景：单元测试快照、UI 缓存、图像滤镜、跨画布纹理复用。
  • WhatsCanvas 的 OutputTarget 五种模式与 saveLayer 的关系。
  • Skia / Cairo / Qt / 浏览器 Canvas 都是如何实现离屏的。
01 · 先看问题

"直接画到屏幕"与"先画到缓冲区"到底差在哪里？

拉动滑块，把绘制目标从"直接到窗口"切换成"先到离屏缓冲区，再合成/读回"。你可以看到多出的一步：一块像素归你所有，可以随时读、拷贝、当纹理。

核心直觉 "渲染"本身不关心画在哪儿。 无论是屏幕像素、CPU 数组，还是 GPU 纹理， Canvas 的绘制命令都是同一批。 唯一的区别是：终点缓冲区的所有权和读回代价。

离屏渲染最朴素的价值是"我把画完的一整帧握在手里，可以再用"。

一个最小对比 屏幕渲染： beginFrame → draw → endFrame → present() 离屏渲染： beginFrame → draw → endFrame → readPixelsRGBA() 或直接把它当纹理复用

最大差别只有最后一步：present() 把结果交给窗口系统，而离屏则保留在你自己的缓冲区里。

02 · 什么时候用离屏

4 种典型场景，各自解决什么问题

① 快照 / 单元测试

把一帧渲染成 PPM/PNG 与基线比对，跑在无窗口 CI 上。

② UI 缓存

把不常变的部分（背景、图表）画到一张纹理里，每帧只重画会变的部分。

③ 图像滤镜 / Layer

对一组绘制做整体 blur / shadow / color-matrix，必须先把它汇聚到一张离屏。

④ 跨画布纹理复用

离屏结果本身能当 ITextureSource，被另一个 Canvas 采样。

① 快照 / 单元测试

Software 后端不需要 GL context，从 Backend::Software 建 Canvas → 画 → readPixelsRGBA 就能得到 RGBA 字节，直接落地 PPM/PNG 与 baseline 比对。这也是 WhatsCanvas SoftwareGoldenTests、parity_probe 的运行方式。

      03 · Software vs OpenGL

      两种后端的离屏"内部长什么样"

      看两条流水线的差异：Software 把结果放进一段 std::vector<uint8_t>（RGBA8 帧缓冲）；OpenGL 会申请 FBO + 附着 RGBA8 纹理 + 可选深度/模板 renderbuffer。读回都用 readPixelsRGBA，但 CPU 侧几乎零成本，GPU 侧要发起 glReadPixels 阻塞往返（异步 API 是 readPixelsRGBAAsync）。

      1. Software：内存直取 src/render/software/SoftwareRenderer.h 里 framebuffer_ 就是一段 RGBA8 数组；行 0 是画布上边缘（row 0 = top），readPixelsRGBA 直接 memcpy。
      2. OpenGL：FBO + 附着纹理 OpenGLRenderDevice::createRenderTarget 里申请一份 GL_RGBA8 纹理 + GL_DEPTH24_STENCIL8 renderbuffer，把它挂到一个 FBO 上；readPixelsRGBA 走 glReadPixels 并在 CPU 侧把行序翻转（GL 默认左下角原点）。
      3. saveLayer 也是"临时离屏" 每次 saveLayer 会开一个和主帧缓冲同规模的临时纹理，restore 时用一次全屏 quad 把它合成回去；这也是 blur / backdropFilter / innerShadow 起效的地方。
      04 · WhatsCanvas 的接口

      OutputTarget 的五种模式，以及一段最小完整代码

      include/wsc/Surface.h 里定义了绘制目标的枚举：

      enum class Kind {
    Offscreen,          // Canvas 自己拥有目标，用 readPixelsRGBA 取回
    OffscreenTexture,   // 同上，但可作纹理被另一个 Canvas 采样
    Window,             // 呈现到 OS 窗口，Canvas 拥有 swapchain / blit
    OpenGLFramebuffer,  // 渲染进宿主拥有的 GL FBO（例如引擎自带的）
    VulkanImage,        // 渲染进宿主拥有的 VkImage
};

      典型的离屏"六行"最小程序（examples/hello_world/main.cpp）：

      auto canvas = wsc::Canvas::create(
    wsc::Canvas::Backend::Software, 256, 256);
canvas->initializeContext();       // Software 不需要 GL context

canvas->beginFrame();
wsc::Paint p; p.setAntiAlias(true);
p.setColor(wsc::Color(40, 120, 240));
canvas->drawRoundRect(
    wsc::RectF(40, 40, 176, 176), 24.0f, p);
canvas->endFrame();

canvas->savePixelsPPM("first.ppm"); // 或 readPixelsRGBA(pixels);

      要把结果拿去当纹理喂给另一个 Canvas，就把 setOutputTarget(OutputTarget::OffscreenTexture()) 放在 beginFrame 之前，Canvas 本身实现了 ITextureSource。

      Offscreen 单元测试首选

      纯 CPU 缓冲区，readPixelsRGBA 一次memcpy；OpenGL/Vulkan 后端也支持，同样走 readPixelsRGBA 从 FBO 读回。

      OffscreenTexture 跨 Canvas 纹理复用

      渲染完的 Canvas 直接 drawImage(canvas, ...) 被另一个 Canvas 采样。
      注意：Software 后端此模式仍是内存缓冲区；只有 GPU 后端能真正做零拷贝。

      Window 上屏

      ToWindow(NativeSurface)：Canvas 掌管 swapchain 和 present。见 examples/present/gl_main.cpp。

      OpenGLFramebuffer / VulkanImage 嵌入宿主渲染管线

      宿主自己拿着 FBO 或 VkImage，WhatsCanvas 只借来"往里画"。适合塞进游戏引擎、Qt/QML 现有的 GL 上下文里。

      陷阱 DPR 与逻辑坐标

      离屏 Canvas 默认 DPR=1；如果你的场景基于 DPR=3 的移动端设计，请显式 setDevicePixelRatio(3.0f)，然后按物理像素 width×3 建 Canvas。否则 golden 会跟真机对不齐。

      05 · UI 缓存演示

      把一张"背景"离屏一次，随后每帧只画会动的部分

      左侧是"背景"（网格 + 大量矩形），右侧是"动画物体"。关闭缓存时，背景要跟着物体一起每帧重画；开启缓存后，背景只画 1 次画进一张纹理，之后每帧只 blit 这张纹理 + 画动画层。

      经验法则 "命令数量 × 每帧调用次数" 是最直接的削减对象。 把不变的一段命令离屏一次， 就换成了每帧 1 次纹理 blit。

      在 WhatsCanvas 里，这就是"用一个 OffscreenTexture Canvas 画背景，主 Canvas 每帧 drawImage 复用它"。

      坑：缓存本身要开一张和目标同规模的纹理。切勿把频繁尺寸变化的东西离屏——每次 resize 都在申请纹理，反而更慢。RenderTargetPool 就是为了缓解这类频繁申请。
      另一种"隐性离屏"：saveLayer。每次调用它就等于额外开一张同尺寸纹理，restore 时合成回主帧缓冲。滤镜 / 全组透明度 / blend group 都是它的用户，用得不加节制会让 GPU 内存翻倍。
      06 · 主流 2D 图形库怎么做

      Skia、Cairo、Qt、浏览器 Canvas 各自怎么描述"离屏"

      Skia

      核心概念是 SkSurface，同时抽象窗口、raster、GPU 纹理与外部 FBO；离屏就是 SkSurface::MakeRaster 或 MakeRenderTarget。toImage() 把它锁成 SkImage 供纹理使用。

      Cairo

      核心是 cairo_surface_t，最常见的离屏是 cairo_image_surface_create；也有 cairo_recording_surface 用来"录制"命令，晚些再回放到具体目标。

      Qt / QPainter

      QPixmap / QImage / QOpenGLFramebufferObject 都能被 QPainter 当目标；QML 场景图里"层"的实现本质也是离屏 FBO 合成。

      浏览器 Canvas 2D

      HTMLCanvasElement 天然就是"离屏"（除非它被 attach 到 DOM）。OffscreenCanvas 更进一步：可在 Worker 线程渲染，主线程只 transferToImageBitmap() 取结果。

      共同点：大家都区分"记录命令的表面"和"最终像素落地的表面"，都提供"离屏 → 纹理"或"离屏 → 图像"的桥接。
      不同点：抽象层级不同——Skia 抽象到 SkSurface，Cairo 抽象到 cairo_surface_t，Qt 用具体设备类，浏览器用 DOM/Worker 二元结构；WhatsCanvas 的 OutputTarget 更像 Skia 那种"目标枚举"。
      07 · 你可以怎么判断

      什么时候上离屏、什么时候不要

      确定要用 单元测试 / CI / server-side thumbnail / 抗锯齿滤镜 / UI 有大量不变的静态层。Software Offscreen 是最省事的方案，一段 readPixelsRGBA 就搞定。
      值得权衡 高频尺寸变化的组件（滚动列表 item、随时缩放的图表）。warn 如果每帧都重建目标纹理，反而更慢；配合 RenderTargetPool 或"只缓存稳定尺寸的图层"再启用。
      建议避免 只画几十条命令的小 UI 组件包一层 saveLayer——离屏本身有开销，得不偿失。rule of thumb 至少有几百条命令、且"每帧只有一小部分会变"时才考虑。
      一句话总结 离屏 = 把渲染结果放在"你能控制的一块缓冲区里"。 它本身几乎不改变绘制命令，但让你多了三件事可做： 读回像素、当纹理复用、把一组命令当整体做滤镜。

      Software 后端做离屏几乎零成本；GPU 后端做离屏是"开一张 FBO + 附着纹理"，一定要衡量往返代价。
